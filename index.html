Explores how HQ and child accounts experience the same CDP conditions. At HQ, conditions evaluate tenant-wide; at child accounts, evaluation is automatically scoped to connected MT locations.

HQ view: Each condition card shows a scope indicator — "Evaluating across all locations" — so the marketer knows their segment pulls from the full brand's CDP data. The indicator disappears if they add a location filter manually.
Child account, locally authored: The condition automatically scopes to Studio A's connected MT location (loc_2847). The "At this location" badge on the card communicates scope. The child user can add additional filters to narrow further, but cannot change to tenant-wide.
Child account, HQ-pushed (unlocked): This condition was authored at HQ and evaluates tenant-wide. The child can see it and add allowed filters, but cannot change the evaluation scope. A "From HQ" banner distinguishes it from locally authored conditions.
Child account, HQ-pushed (locked): This condition is fully locked by HQ. The child can read it but cannot interact with it. A locked banner explicitly states that it evaluates across all locations, so there is no ambiguity about what the condition is doing.
